1. Type 1 (Bare-Metal) vs Type 2 (Hosted) Hypervisors
Unit 4 · 7 Marks 99% Probability

Question Format: "Differentiate between Type 1 and Type 2 Hypervisors with a neat diagram. Discuss their architectures, pros, cons, and give two examples of each."

4-Point Answer Blueprint:
  • Architecture: Type 1 sits directly on bare-metal hardware (no host OS); Type 2 sits as an application on top of a host OS (Windows/Linux).
  • Performance & Overhead: Type 1 has near-native hardware speed and low latency; Type 2 suffers double OS context switching and high overhead.
  • Security & Isolation: Type 1 has strong VM isolation; Type 2 is vulnerable to host OS compromise (if host OS crashes, all VMs crash).
  • Examples: Type 1: VMware ESXi, Microsoft Hyper-V, KVM, Xen. Type 2: Oracle VirtualBox, VMware Workstation.

2. Three Core Modules of Hypervisors: Dispatcher, Allocator & Interpreter
Unit 4 · 7 Marks 95% Probability

Question Format: "Explain the internal architecture of a hypervisor. Describe the roles of Dispatcher, Allocator, and Interpreter/Executor with a schematic diagram."

4-Point Answer Blueprint:
  • Dispatcher: The traffic controller. Intercepts privileged CPU instructions and routes them to the Allocator or Interpreter.
  • Allocator: Decides how physical resources (CPU cores, RAM pages, disk blocks) are allocated to requesting VMs without collision.
  • Interpreter / Executor: Emulates sensitive instructions that cannot be executed directly by the hardware without violating isolation.
  • Popek-Goldberg Theorem: For a computer architecture to be virtualizable, all sensitive instructions must be a subset of privileged instructions.

3. Virtual Machines vs Docker Containers (Hardware vs OS Virtualization)
Unit 4 · 7/10 Marks 99% Probability

Question Format: "Compare Virtual Machines and Containers on at least six parameters. Draw neat architectural diagrams for both."

4-Point Answer Blueprint:
  • Virtualization Level: VM virtualizes physical hardware (CPU, RAM, NIC); Container virtualizes OS kernel using namespaces and cgroups.
  • Guest OS Requirement: VM requires a dedicated, full Guest OS per instance (~GBs); Container shares Host OS kernel (MBs).
  • Startup Time: VMs boot in minutes (full OS boot); Containers launch in milliseconds (instant process spawn).
  • Isolation & Density: VMs provide hard hardware-level boundary; Containers provide process-level isolation with 5–10x higher server density.

5. Software-Defined Networking (SDN) 3-Plane Architecture & OpenFlow
Unit 4 · 7 Marks 95% Probability

Question Format: "What is SDN? Explain its 3-tier architecture with a neat diagram. Contrast the Data Plane, Control Plane, and Management Plane."

4-Point Answer Blueprint:
  • Concept: Decouples the network control logic (Control Plane) from physical packet forwarding routers/switches (Data Plane).
  • Application Plane (Top): Network monitoring, security policies, and load balancing applications communicating via Northbound REST APIs.
  • Control Plane (Middle): The centralized SDN controller (the "brain") that calculates routing topologies and injects flow rules.
  • Data Plane (Bottom): High-speed hardware switches that simply forward packets according to flow tables via Southbound APIs (OpenFlow).

6. Cloud Storage Comparison: Block vs Object vs File Storage
Unit 4 · 7 Marks 90% Probability

Question Format: "Compare Block Storage, Object Storage, and File Storage on use cases, structure, latency, protocols, and cloud services (AWS/Azure/GCP)."

4-Point Answer Blueprint:
  • Block Storage (EBS, Persistent Disk): Data split into fixed raw blocks with unique addresses; ultra-low latency; ideal for OS boot disks and transactional databases (MySQL).
  • Object Storage (S3, Cloud Storage): Data stored as complete immutable objects with custom metadata and globally unique ID in a flat namespace; accessed via REST API (HTTP GET/PUT); infinite scale; ideal for media, backups, data lakes.
  • File Storage (EFS, Azure Files): Hierarchical folder/file structure; accessed via standard NFS/SMB network protocols; shared across multiple servers concurrently.

Unit 5 · 7 Marks 95% Probability

Question Format: "Explain the CIA Triad in the context of cloud security. What controls protect Confidentiality, Integrity, and Availability?"

8. AWS IAM Architecture & Policy Evaluation Flowchart (Prof. Amin Shaikh)
Unit 5 · 7 Marks 99% Probability

Question Format: "Explain AWS IAM policy evaluation logic with a flowchart. Discuss the significance of the Explicit Deny Rule and Principle of Least Privilege."

4-Point Answer Blueprint:
  • Default Decision: All requests begin with an implicit default DENY.
  • Golden Rule 1 (Explicit Deny): An explicit `"Effect": "Deny"` in ANY matching policy unconditionally overrides any number of `"Allow"` statements!
  • Golden Rule 2 (Explicit Allow): If no explicit deny exists, there must be at least one explicit `"Effect": "Allow"` for access to be granted; otherwise, it remains denied.
  • Principle of Least Privilege (PoLP): Grant users only the minimum permissions necessary to accomplish their assigned job role for the minimum required duration.

9. Cloud Security Incident Case Studies (Capital One & Storm-0558)
Unit 5 · 10 Marks 90% Probability

Question Format: "Analyze any two major real-world cloud security breaches. Discuss the root causes, attack vectors, and preventative controls."

4-Point Answer Blueprint:
  • Capital One (2019): SSRF on misconfigured open-source WAF querying AWS IMDSv1 (`169.254.169.254`) → exfiltrated IAM role credentials → accessed 106M credit applications in S3. Fix: IMDSv2 (session token header required), restrictive IAM.
  • Microsoft Storm-0558 (2023): Stolen MSA signing key from crashed Windows kernel memory dump → forged OpenID tokens → breached 25 government email inboxes. Fix: Secure key rotation, HSM-enforced token signing.
  • Code Spaces (2014): Lack of MFA on AWS root account → hacker deleted all EBS volumes and S3 backups → company forced into complete liquidation. Fix: Never use root, enforce MFA.
10. Multi-Tenant Architecture: Silo vs Bridge vs Pool Database Isolation
Unit 3 · 7 Marks 95% Probability

Question Format: "What is Multi-Tenancy? Compare Silo, Bridge, and Pool data isolation patterns with respect to cost, security, performance, and blast radius."

4-Point Answer Blueprint:
  • Definition: Software architecture where a single instance of an application serves multiple distinct customer organizations (tenants).
  • Silo Pattern: Separate physical database instance per tenant. Maximum isolation, zero cross-tenant blast radius, highest cost (used by Banks/Gov).
  • Bridge Pattern: Shared database engine, separate database schemas per tenant. Moderate isolation and cost.
  • Pool Pattern: Shared database and shared tables; data segregated logically via `tenant_id` column. Lowest cost, maximum resource efficiency, requires robust Row-Level Security (RLS).

3 Sub-topics ▼
▶ 1.1 What is Cloud Computing? Definition & Google Drive Real-World Example
Definition ▼
Exam-Ready Definition: Cloud Computing is the on-demand delivery of computing services (including servers, storage, databases, networking, software, analytics, and artificial intelligence) over the Internet ("the cloud"), providing flexible, affordable, effective, and efficient resources for the development, execution, and scaling of applications without requiring users to purchase and maintain physical infrastructure.

Real-Life Example: Google Drive

  • Without Cloud Computing: You must purchase physical hard drives or USB flash drives, store files locally, and if the laptop crashes or is stolen, access to those files is permanently lost.
  • With Cloud Computing: You upload files to Google Drive; files reside securely on redundant Google cloud infrastructure; you can access and collaborate on them from any smartphone or laptop worldwide without maintaining a single physical storage drive.
▶ 1.2 The 5 Essential Characteristics of Cloud Computing (NIST SP 800-145)
5 Marks ▼

1. On-Demand Self-Service

A consumer can unilaterally provision computing capabilities, such as server time and network storage, as needed automatically without requiring human interaction with each service provider.

2. Broad Network Access

Capabilities are available over the network and accessed through standard mechanisms that promote use by heterogeneous thin or thick client platforms (e.g., mobile phones, tablets, laptops, and workstations).

3. Resource Pooling

The provider's computing resources are pooled to serve multiple consumers using a multi-tenant model, with different physical and virtual resources dynamically assigned and reassigned according to consumer demand.

4. Rapid Elasticity

Capabilities can be elastically provisioned and released, in some cases automatically, to scale rapidly outward and inward commensurate with demand. To the consumer, available resources often appear infinite.

5. Measured Service (Pay-as-You-Go)

Cloud systems automatically control and optimize resource use by leveraging a metering capability at some level of abstraction appropriate to the type of service (e.g., storage, processing, bandwidth, active user accounts).

▶ 1.3 How Cloud Computing Works (Step-by-Step Flow)
Workflow ▼
  1. Client Connection: User establishes an Internet connection via browser, app, or CLI.
  2. Service Request: User initiates a request (e.g., login, file save, database query).
  3. Routing & Load Balancing: Cloud network gateways authenticate credentials and route traffic.
  4. Virtualized Processing: Hypervisors and container clusters execute business logic.
  5. Persistence: Data is read or written to distributed storage arrays across multiple AZs.
  6. Response Delivery: Result is encrypted and transmitted back to the client device.

▶ 2.1 The 12 Benefits of Cloud Computing (From Lecture Slides)
12 Benefits ▼
1. Cost Efficiency: Eliminates upfront CapEx; pay only for resources consumed on a utility basis.
2. Scalability: Effortlessly scale compute power up or out to handle growing user workloads.
3. High Availability: Redundant multi-AZ datacenters ensure 24x7 operations with automated failover.
4. Ubiquitous Accessibility: Access applications from anywhere across smartphones, tablets, and PCs.
5. Backup & Disaster Recovery: Automated snapshots and cross-region replication prevent permanent data loss.
6. Enterprise Security: End-to-end encryption, IAM access controls, MFA, and automated threat detection.
7. Architectural Flexibility: Freedom to choose OS, programming languages, runtimes, and databases.
8. Real-Time Collaboration: Simultaneous multi-user editing (Google Docs, Microsoft 365, Slack).
9. Automatic Updates: Provider handles zero-downtime security patching and software updates.
10. Superior Performance: High-speed NVMe SSDs, low-latency backbones, and smart load balancing.
11. Global Reach: Deploy applications in dozens of international regions within minutes.
12. Environmental Sustainability: High server utilization reduces power waste and carbon footprint.
▶ 2.2 The 10 Major Challenges of Cloud Computing (From Lecture Slides)
10 Challenges ▼
  1. Security & Privacy: Threat of data leakage, malware, and unauthorized access in shared multi-tenant hosts.
  2. Internet Dependency: Cloud access is strictly gated by stable, high-speed Internet connectivity.
  3. Downtime & Service Outages: Hyperscaler outages (e.g. AWS us-east-1 disruptions) can temporarily halt business operations.
  4. Vendor Lock-in: Incompatible proprietary APIs, databases, and high data egress fees make switching providers painful.
  5. Data Loss & Recovery Risks: Inadequate snapshot schedules or misconfigured retention policies can risk accidental loss.
  6. Compliance & Legal Jurisdiction: Strict compliance laws (GDPR, HIPAA, RBI localization) restrict off-shore data storage.
  7. Cost Management & Bill Shock: Unmonitored zombie VMs, unattached disks, and high egress traffic cause soaring bills.
  8. Performance Jitter: Network latency and noisy neighbors sharing the same physical CPU/storage degrade responsiveness.
  9. Limited Infrastructure Control: Users have zero control over bare-metal hardware, hypervisor versions, or physical switches.
  10. Migration & Technical Skill Gaps: Refactoring monolithic legacy apps to cloud-native microservices requires rare skills.

▶ 4.1 Cloud Infrastructure Definition & Principal / College Campus Analogy
Analogy ▼
Cloud Infrastructure Management: The structured operational process of monitoring, controlling, maintaining, securing, and optimizing all cloud resources (compute, storage, network, identity, and billing) to ensure continuous high availability, security, and cost efficiency.

The College Principal Campus Analogy (From Lecture Slides)

Imagine you are the Principal of a university college campus:

  • You must oversee and manage classrooms, electricity generators, water supply, security staff, campus Wi-Fi, teaching faculty, and maintenance schedules.
  • Similarly, a Cloud Administrator oversees and manages Virtual Machines, storage buckets, virtual private networks, firewall security groups, user access privileges, and automated data backups.
▶ 4.2 Resource Provisioning: Manual vs Automatic (Restaurant Analogy)
Provisioning ▼
Resource Provisioning: The allocation and deployment of cloud resources (VMs, storage, networking) according to user demands and application requirements.
  • Manual Provisioning: An administrator logs into the cloud console (e.g. AWS Management Console) and manually clicks through to create an EC2 virtual machine and configure disk storage.
  • Automatic Provisioning: Cloud systems monitor workload metrics (e.g. CPU > 80%) and automatically spawn additional virtual instances using Auto Scaling without human intervention.

The Restaurant Working Analogy: When a restaurant experiences a sudden rush of customers during dinner time, the manager opens up additional dining tables, calls in reserve waiters, and powers on backup cooking stoves. Once the rush ends, extra tables are closed. This is exactly how cloud Auto Scaling operates!

▶ 4.3 Cloud Infrastructure Monitoring & The Amazon CloudWatch 95% CPU Case
Monitoring ▼

Infrastructure Monitoring continuously checks the operational health, availability, and performance telemetry of cloud resources:

  • Key Metrics Monitored: CPU Utilization (%), RAM Usage, Disk Read/Write IOPS, Network In/Out Bandwidth, HTTP Response Latency, and Error Rates.
  • AWS Monitoring Tool: Amazon CloudWatch collects telemetry metrics, tracks log events, and triggers automated alarm actions.
Real-World Monitoring Flow (Lecture Slides Case):
Suppose an e-commerce database instance experiences a CPU utilization surge to 95%:
  1. CloudWatch detects CPU crossing the 85% threshold rule.
  2. An automated CloudWatch Alarm triggers an Amazon SNS notification to the SRE team.
  3. Concurrently, an Auto-Scaling policy triggers the provisioning of a read-replica database to relieve query pressure, preventing server crash.

▶ 6.2 Virtual Machines (VMs), 5 Components & Server Slicing Example
VM Structure ▼

A Virtual Machine (VM) is a software emulation of a physical computer containing:

  • vCPU: Virtual CPU cores scheduled onto physical cores.
  • Virtual Memory: Virtual RAM address space allocated from physical RAM.
  • Virtual Disk: An image file (e.g. .vmdk, .qcow2) representing physical hard drive storage.
  • Virtual NIC: Emulated network card with unique MAC address and virtual IP.
  • Guest OS: Full operating system (Ubuntu, Windows Server) running inside the VM.

Server Slicing Example (From Lecture Slides)

Consider a physical server with 16 CPU Cores and 64 GB RAM:

  • VM 1 (Web Server): Allocated 4 Cores + 16 GB RAM (Linux OS)
  • VM 2 (Database Server): Allocated 6 Cores + 24 GB RAM (Linux OS)
  • VM 3 (Application Server): Allocated 4 Cores + 16 GB RAM (Windows Server OS)
  • VM 4 (Testing Environment): Allocated 2 Cores + 8 GB RAM (Linux OS)

Result: 100% of physical capacity is utilized without resource wastage!

▶ 1.3 Public Cloud — Characteristics, Architecture, Pros/Cons & Global Examples
Public Cloud ▼
Public Cloud: A computing model where infrastructure and computing resources are owned, operated, and maintained by a third-party cloud service provider and delivered to multiple organizations (tenants) over the public Internet on a pay-as-you-go basis.

Core Characteristics

  • Third-Party Owned: Providers like Amazon, Microsoft, and Google own the physical servers, switches, and cooling facilities.
  • Multi-Tenancy: Multiple unrelated customers share the same physical hardware pools through logical hypervisor isolation.
  • Pay-As-You-Go (Utility Pricing): Billed strictly for compute seconds, gigabytes stored, and data transferred.
  • Near-Infinite Elasticity: Instantly scale from 1 server to 10,000 servers without ordering hardware.

Advantages & Limitations

Advantages (Pros)

  • Zero CapEx: No server hardware purchases or datacenter leasing costs.
  • High Availability: Global footprint across multiple Regions and Availability Zones.
  • Rapid Deployment: Provision complex multi-tier clusters in minutes via web console or CLI.
  • Zero Maintenance Duty: Hardware lifecycle, power cooling, and physical security handled by provider.

Limitations (Cons)

  • Loss of Physical Control: Zero access to bare-metal hardware or physical storage drives.
  • Multi-Tenant Jitter: Risk of "noisy neighbors" degrading shared resource throughput.
  • Regulatory Barriers: Strict data sovereignty laws may prohibit storing customer records off-premises.
  • Uncontrolled Cost Risk: Idle VMs and unmonitored egress traffic can cause bill shock.

Real-World Case Studies (From Lecture Slides)

  • Netflix: Migrated 100% of its streaming services, video encoding pipelines, and recommendation engine onto AWS public cloud infrastructure.
  • Spotify: Leverages Google Cloud Platform (GCP) for data storage, audio streaming, and personalized recommendation analytics.
  • The New York Times: Processed and digitized its historical archives (millions of scanned newspaper pages) using GCP compute instances in just a few days.
▶ 1.4 Private Cloud — On-Premises vs Hosted, Architecture & Indian Examples
Private Cloud ▼
Private Cloud: Cloud infrastructure provisioned for exclusive use by a single organization comprising multiple consumers (e.g. business units). It may be owned, managed, and operated by the organization, a third party, or some combination of them, and it may exist on or off premises.

Two Deployment Types of Private Cloud

  • 1. On-Premises Private Cloud: Hosted inside the organization's own physical datacenter. Complete internal control, managed by corporate IT staff. Highest security and upfront CapEx.
  • 2. Third-Party Hosted (Dedicated) Private Cloud: Hosted in an external provider's facility (e.g., Equinix, Rackspace, AWS Dedicated Hosts), but the physical servers and network are physically or logically dedicated exclusively to that single enterprise.

Key Architecture Components

Physical Servers → Bare-Metal Hypervisors (KVM, ESXi) → Virtualized VM & Container Pools → Private SAN/NAS Storage → Software-Defined Networking (SDN) → Corporate Identity Management (LDAP/Active Directory) → Cloud Management Platform (OpenStack / CloudStack).

Indian Real-World Examples (From Lecture Slides)

  • UIDAI (Aadhaar): Runs dedicated private cloud infrastructure to store and verify biometric and demographic records of 1.4+ billion Indian residents with zero external data sharing.
  • Public & Private Banks (e.g. Indian Bank, SBI): Utilize on-premises private clouds for core banking solutions (CBS) to comply with Reserve Bank of India (RBI) data localization mandates.
  • Telecom Giants (Tata Communications, Reliance Jio, Airtel): Maintain massive internal private clouds to manage core cellular switching, 5G packet cores, and billing infrastructure.
▶ 1.5 Hybrid Cloud — Architecture, Working, Benefits & Cloud Bursting
Hybrid Cloud ▼
Hybrid Cloud: An infrastructure composition of two or more distinct cloud environments (commonly a Private Cloud and a Public Cloud) that remain unique entities but are bound together by standardized technology enabling data and application portability.

Working Architecture & Banking Example

Consider an enterprise banking platform:

  • Sensitive Workloads (Private Cloud): Core account ledgers, customer credit histories, and sensitive transactions remain secured on the private on-premises datacenter.
  • Customer-Facing Workloads (Public Cloud): Mobile banking front-ends, promotional campaign micro-sites, and statement PDF generators run on AWS/Azure public cloud for elastic scale.
  • Secure Interconnect: Bound together via encrypted IPsec VPN tunnels or dedicated private fiber connections (AWS Direct Connect / Azure ExpressRoute).
⚡ Cloud Bursting: A dynamic application deployment model where an application runs normally in a private cloud or datacenter, but during sudden demand surges that exceed internal compute limits, it automatically "bursts" excess workloads into a public cloud to prevent crashes.
▶ 1.6 Community Cloud — Shared Sectoral Infrastructure & 4 Core Applications
Community Cloud ▼
Community Cloud: A cloud infrastructure shared exclusively by multiple organizations that have common requirements, shared missions, uniform security concerns, or industry-specific regulatory compliance mandates.

4 Primary Applications (From Lecture Slides)

  • 2. Universities & Research Laboratories: Academic institutions connect supercomputers and research datasets, pooling compute cycles for joint genomics, physics, and climate simulation research.
  • 3. Government Agencies: Local municipal and state government departments share a dedicated government cloud (e.g., MeghRaj in India, AWS GovCloud) sharing security tooling and disaster recovery costs.
  • 4. Banks & Credit Unions: Regional financial institutions collaborate on a shared banking community cloud for inter-bank transaction settlement, fraud intelligence sharing, and RBI compliance.
▶ 1.7 Multi-Cloud Strategy — Definition, Rationale, Pros & Cons
Multi-Cloud ▼
Multi-Cloud: The operational strategy of using cloud computing services from two or more independent cloud service providers (e.g. AWS + Microsoft Azure + Google Cloud) simultaneously for distinct enterprise workloads.

Why Enterprises Adopt Multi-Cloud (Workload Distribution)

  • AWS: Best-in-class raw compute (EC2) and massive global footprint for international web apps.
  • Microsoft Azure: Seamless enterprise Active Directory (Entra ID), Office 365, and Windows Server integration.
  • Google Cloud (GCP): Industry-leading big data processing (BigQuery) and advanced machine learning (Vertex AI).
  • Specialized Provider: Cold archive storage or disaster recovery backup target.

Advantages vs. Operational Challenges

  • Key Advantages: Eliminates single-vendor lock-in, increases negotiation leverage, provides superior disaster recovery (if one hyperscaler suffers an outage, the other remains live), and leverages specialized best-of-breed features.
  • Operational Challenges: High management complexity, disparate security configurations across consoles, high egress data transfer fees between providers, and necessity for multi-cloud tooling (Terraform, Kubernetes).

▶ 2.4 Geographic Distribution: Regions vs Availability Zones
Regions & AZs ▼

Geographic Region

A separate physical geographic area around the world (e.g. ap-south-1 in Mumbai, us-east-1 in N. Virginia). Each Region is completely isolated from other regions to achieve fault tolerance and satisfy national data sovereignty regulations.

Availability Zone (AZ)

One or more discrete physical datacenters located within a Region, each with independent power, cooling, and networking. AZs are connected via ultra-low-latency private fiber. Designing apps across multi-AZs ensures zero downtime even if a lightning strike or flood takes down an entire datacenter.

Virtualization ▼

  • Type 1 Hypervisors: Bare-metal hypervisors (KVM, VMware ESXi) drive cloud hyperscaler infrastructure for raw bare-metal efficiency.
  • Resource Pooling: Dynamically slices and overcommits CPU, RAM, and network bandwidth according to tenant demand.

Compute ▼
Compute Layer: Provides CPU processing, memory execution, and application compute engines dynamically allocated to meet variable workload requests.

▶ 3.2 Storage Architecture (Block, Object, File & Replication)
Storage ▼
Storage Architecture: Provides scalable, network-accessible data storage characterized by high durability, automatic multi-AZ replication, access control, and tiered encryption.
  • Block Storage: Raw addressable block volumes mounted over SAN/iSCSI for VM boot disks and low-latency databases (e.g. AWS EBS, Azure Managed Disks, GCP Persistent Disk).

Elasticity ▼
Elasticity: The degree to which a cloud system is able to adapt to workload changes by provisioning and de-provisioning resources in an automated manner, such that at each point in time the available resources match the current demand as closely as possible.

▶ 4.4 Load Balancing — Request Distribution Workflow & Health Checks
Load Balancing ▼
Load Balancer: A reverse-proxy network device or managed service that acts as a single point of entry to accept incoming application traffic and intelligently distribute requests across a pool of healthy backend servers.

Step-by-Step Request Distribution Workflow

  1. Client Request: User browser initiates an HTTPS request to example.com.
  2. Load Balancer Ingestion: The public Load Balancer terminates the TLS handshake and ingests the request.
  3. Health Check Evaluation: Checks its dynamic registry to filter out servers marked unhealthy.
  4. Algorithm Execution: Applies configured routing algorithm (Round Robin, Least Connections, IP Hash) to select an optimal server.
  5. Forwarding & Processing: Forwards request to private IP of selected worker; worker generates response.
  6. Return Response: Load balancer delivers response back to client transparently.
▶ 4.5 High Availability vs Fault Tolerance & Availability Calculation Formula
HA vs FT ▼

High Availability (HA)

Ensures the system remains accessible and operational for a specified percentage of time (e.g. 99.9% or 99.99%) with minimal perceptible downtime. Leverages automated failover clusters, load balancers, and multi-AZ deployments.

Fault Tolerance (FT)

The aggressive capability of a system to continue functioning with zero downtime and zero data loss even when one or more underlying physical components fail completely. Relies on 100% hot duplicate hardware mirroring.

High Availability Mathematical Formula (From Lecture Slides)

$$\text{Availability (\%)} = \frac{\text{Uptime}}{\text{Uptime} + \text{Downtime}} \times 100$$

Example Problem: If a cloud portal operates for 999 hours in a month and experiences 1 hour of total unexpected downtime:

$$\text{Availability} = \frac{999}{999 + 1} \times 100 = \frac{999}{1000} \times 100 = 99.9\% \quad (\text{Three Nines})$$

▶ 5.1 Multi-Tenant Architecture Definition, Tenant Concept & SaaS Real-World Examples
Definition ▼

▶ 5.3 The 3 Database Isolation Patterns: Pool, Bridge & Silo
Isolation Patterns ▼

1. Pool Pattern (Shared DB / Shared Table)

All tenants share the exact same database tables. Every row includes a mandatory tenant_id partition key. Isolation is enforced through application SQL filters or database Row-Level Security (RLS).

Pros: Lowest cost, simplest management.
Cons: Highest risk of cross-tenant data leak if SQL filter is missed.

2. Bridge Pattern (Shared DB / Separate Schema)

All tenants reside in the same physical database engine instance, but each tenant receives their own dedicated database Schema (e.g. schema_tenant_a, schema_tenant_b).

Pros: Balanced cost and logical schema isolation.
Cons: Migrations must run across hundreds of schemas.

3. Silo Pattern (Database-per-Tenant)

Each tenant gets a completely dedicated database instance. Zero shared tables, zero shared schemas. Dedicated connection credentials and isolated disk storage.

Pros: Maximum isolation, compliance, zero cross-tenant leak.
Cons: Highest cost, idle DB resource waste.

▶ 5.5 Multi-Tenant Security & The Noisy Neighbor Problem
Challenges & Fixes ▼
The Noisy Neighbor Problem: In a shared multi-tenant environment, if one tenant experiences a sudden massive traffic surge or runs unoptimized database queries, it consumes disproportionate CPU, RAM, disk I/O, or connection pool bandwidth, severely degrading performance for all other innocent tenants on the same server.

Effective Mitigation Strategies

  • Tenant Resource Quotas: Enforce strict CPU/memory limits per tenant using Linux cgroups or container constraints.
  • API Rate Limiting & Throttling: Enforce token-bucket rate limits per tenant_id (e.g. max 500 requests/minute).
  • Dedicated Connection Pooling: Avoid a single global database pool; allocate partitioned pools to prevent exhaustion.
  • Tiered Silo Migration: Automatically migrate high-volume enterprise "whale" tenants into dedicated Silo instances.
  • Tenant-Specific Encryption Keys: Protect sensitive tenant rows using distinct AWS KMS encryption keys.

▶ 6.4 The 6 Load Balancing Algorithms (From Lecture Slides)
Algorithms ▼
  • 1. Round Robin: Cyclically distributes incoming requests sequentially down the server list (Request 1 → Server 1, Request 2 → Server 2, Request 3 → Server 3, Request 4 → Server 1). Best when all servers have identical hardware specs.
  • 2. Weighted Round Robin: Assigns numerical weights proportional to server processing power (e.g. Server 1 weight 3, Server 2 weight 1; Server 1 receives 3x more requests).
  • 3. Least Connections: Routes the incoming request to the server that currently has the lowest active open client connections. Ideal for transactions with variable processing durations.
  • 4. Weighted Least Connections: Considers both current open connections and the baseline capacity/weight of each server node.
  • 5. IP Hash: Hashes the client's source IP address to determine the target backend server. Ensures session stickiness (the same client consistently reaches the same server).
  • 6. Response Time Based: Directs requests to servers exhibiting the fastest health-check ping and lowest response latency.

▶ 6.6 Cloud Distributed Systems: CDN Edge Caching & API Communication
CDN & APIs ▼

Content Delivery Networks (CDN) as a Distributed System

A CDN (e.g. AWS CloudFront, Cloudflare, Akamai) is a geographically distributed network of edge cache servers designed to deliver web assets at lightning speeds:

  • Edge Location Caching: When a user in Mumbai requests a video hosted in Virginia, the CDN caches the video at a local Point of Presence (PoP) in Mumbai.
  • Cache Hit vs Cache Miss: If cached, the asset is delivered instantly from Mumbai (Cache Hit). If missing, it fetches once from Virginia (Origin Fetch), caches it, and serves subsequent users locally.

APIs as Distributed Connectors

Application Programming Interfaces (REST/JSON, gRPC) serve as the standard contracts enabling decoupled distributed services to exchange records without knowing internal database schemas.

▶ 1.5 Hypervisor Reference Model (Dispatcher, Allocator, Interpreter)
PPT Pages 9-10 ▼

The Hypervisor Reference Model breaks down the internal instruction-handling mechanisms of a Virtual Machine Monitor (VMM) into 3 vital internal sub-modules:

1. Dispatcher

Acts as the central entry gate of the monitor. Intercepts incoming instructions issued by guest VMs and routes them to the appropriate handler routines (Allocator or Interpreter).

2. Allocator

Decides how system resources (CPU slices, memory pages, I/O bandwidth) are allocated to each requesting virtual machine without starving others.

3. Interpreter

Contains trap-and-emulate routines that safely execute privileged instructions (e.g. CPU control register edits) without compromising host stability.

Memory Formula: Dispatcher = Directs | Allocator = Allocates | Interpreter = Interprets.

What is Block Storage?

▶ 9.3 Load Balancing — Layer 4 NLB vs Layer 7 ALB & 5 Core Algorithms
Algorithms ▼

Distributes incoming network traffic across multiple healthy backend servers.

Network Load Balancer (NLB) — Layer 4

Operates at Transport Layer (TCP/UDP). Routes based on IP and port with ultra-high throughput (millions of requests/sec).

Application Load Balancer (ALB) — Layer 7

Operates at Application Layer (HTTP/HTTPS). Inspects URL paths (/api vs /images) and headers for microservice routing.

5 Load Balancing Algorithms:
  • Round Robin: Sequential, circular distribution (Server 1 → Server 2 → Server 3 → Server 1).
  • Weighted Round Robin: Allocates proportionally more requests to higher-capacity servers.
  • Least Connections: Directs traffic to the server currently handling the fewest active client connections.
  • IP Hash: Computes a hash of the client's IP to deterministically bind a client to the same server.
  • Least Response Time: Directs requests to the backend server with the lowest response latency.
▶ 9.4 Content Delivery Network (CDN) — Edge Caching & Cache Hit vs Miss
Edge Caching ▼

A distributed network of geographically dispersed edge servers that caches copies of static assets closer to end users.

Cache Hit

The edge POP already has the requested file cached → returns it instantly to the user without contacting origin.

Cache Miss

Edge server lacks the asset → fetches from origin server, caches a copy locally, and returns asset to user.

  • Noisy Neighbor Syndrome: Addressed via CPU/RAM quota limits enforced by hypervisors and cgroups.
  • Side-Channel Attacks: CPU microarchitectural mitigations (Spectre/Meltdown patches).
▶ 2.3 The 3 States of Data Encryption
Encryption ▼

1. Encryption at Rest

Protects static data saved on storage media (disks, databases, S3 buckets, archives). Encrypted via AES-256 with KMS keys.

2. Encryption in Transit

Protects data traveling over public or private networks between client and server. Secured via TLS 1.3, HTTPS, and IPsec VPN.

3. Encryption in Use

Protects active data in CPU cache and RAM during active processing using hardware Confidential Computing (Intel SGX, AMD SEV).

▶ 7.1 Scalability: Vertical (Scale Up), Horizontal (Scale Out), Diagonal
Scalability ▼

Vertical (Scale Up)

Adding more CPU cores or RAM to an existing machine (e.g. 4GB → 16GB RAM). Limited by physical hardware boundaries; requires reboot downtime.

Horizontal (Scale Out)

Adding more server nodes/instances to the computing pool behind a load balancer (e.g. 2 → 6 instances). High fault tolerance.

Diagonal Scaling

Combines vertical and horizontal: scale up individual instances first, then scale out horizontally as traffic expands.

Elasticity ▼
What is Elasticity?
Elasticity is the ability of cloud computing resources to automatically scale up/out during demand spikes and scale down/in when demand subsides, optimizing costs dynamically.

Example: An online shopping portal runs on 2 servers during regular hours, automatically scales to 10 servers during Black Friday sales, and contracts back to 2 servers afterward.

[2 Marks] Define Cloud Bursting in a Hybrid Cloud model. ▼

Model Answer:

[2 Marks] What is the CIA Triad in Cloud Data Security? ▼

Model Answer:

The CIA Triad is a fundamental security benchmark consisting of:

  • Confidentiality: Preventing unauthorized access to sensitive data (via AES-256 encryption and IAM).

[5 Marks] Explain the Hypervisor Reference Model (Dispatcher, Allocator, Interpreter). ▼

Model Answer:

The Hypervisor Reference Model (from lecture slides 9–10) decomposes a Virtual Machine Monitor into three core internal modules:

  1. Dispatcher: Serves as the primary entry point of the VMM. It traps all instructions issued by guest virtual machines, inspects their privilege level, and reroutes non-privileged calls or passes privileged instructions to the Allocator or Interpreter.
  2. Allocator: Decides and administers physical resource distribution. Whenever a VM requests additional RAM, vCPU cycles, or storage blocks, the Allocator applies scheduling algorithms to allocate system hardware safely without resource starvation.
  3. Interpreter: Contains specific trap routines that simulate privileged machine instructions executed by the guest OS (such as modifying hardware control registers or page tables), executing them in a protected context without compromising the host.
[5 Marks] Differentiate High Availability (HA) and Fault Tolerance (FT) with the Availability Formula. ▼

Model Answer:

$$\text{{Availability (\%)}} = \frac{{\text{{Uptime}}}}{{\text{{Uptime}} + \text{{Downtime}}}} \times 100$$

[7 Marks] Explain Multi-Server 3-Tier Web Architecture and Layer 4 vs Layer 7 Load Balancing. ▼

Model Answer:

A Multi-Server 3-Tier Architecture decouples an application into three independent layers:

  • Tier 1: Web Tier (Presentation): Reverse proxy and web servers (Nginx/Apache) behind a Load Balancer terminating SSL and serving static assets.
  • Tier 2: Application Tier (Business Logic): Auto-scaling worker cluster processing business logic and REST APIs, paired with an in-memory Redis cache.
  • Tier 3: Database Tier (Persistence): Primary Master database (Writes) replicating asynchronously to Read-Replicas (Reads) across multiple AZs.

Layer 4 vs Layer 7 Load Balancing:

  • Layer 4 (Transport / NLB): Routes traffic based on IP address and TCP/UDP port without inspecting application packet content. Ultra-fast, sub-millisecond latency.
  • Layer 7 (Application / ALB): Routes traffic based on application payload (HTTP URLs, headers, hostnames, cookies). Performs smart content-based routing (e.g. /api → App servers, /images → S3).
[10 Marks] Explain Multi-Tenant Architecture. Compare Pool, Bridge, and Silo patterns and explain the Noisy Neighbor problem. ▼

Model Answer:

Multi-Tenant Architecture: A software design where a single software instance runs on shared cloud servers, serving multiple distinct customer organizations (tenants), while strictly isolating each tenant's data, custom settings, and user permissions.

The 3 Database Isolation Patterns:

PatternDatabase InstanceSchemaIsolation LevelCost & Best Use Case
1. Pool Pattern100% SharedShared Tables (tenant_id column)Logical (via Row-Level Security)Lowest cost; high-volume B2C SaaS.
2. Bridge PatternShared EngineSeparate Schema per TenantMedium (Schema boundaries)Moderate cost; mid-market SaaS.
3. Silo PatternDedicated DB per TenantDedicated SchemasMaximum (Physical DB separation)Highest cost; Banks, Healthcare, Defense.

The Noisy Neighbor Problem: In a shared multi-tenant host, if one tenant executes unoptimized queries or experiences a massive traffic spike, it consumes disproportionate CPU, RAM, or connection pool sockets, starving other innocent tenants.

Mitigation Strategies: (1) Enforce per-tenant CPU/RAM cgroup quotas, (2) Apply token-bucket API rate limits per tenant_id, (3) Use partitioned database connection pools, (4) Migrate heavy "whale" tenants into dedicated Silo instances.

[10 Marks] Explain OpenStack Architecture and detail all 9 Core Components with VM creation workflow. ▼

Model Answer:

OpenStack is an open-source IaaS cloud operating system that controls pools of compute, storage, and networking resources throughout a datacenter.

The 9 Core Components:

  • 1. Nova (Compute): Manages the lifecycle of virtual machine instances.
  • 2. Neutron (Networking): Provides virtual SDN networking, subnets, routers, floating IPs, and ports.
  • 3. Keystone (Identity): Central authentication, token issuing, and service catalog endpoint discovery.
  • 4. Glance (Image): Image registry storing base VM disk images and operating system templates.
  • 5. Cinder (Block Storage): Manages persistent block storage volumes attached to VMs.
  • 6. Swift (Object Storage): Scalable, highly durable multi-tenant object storage for unstructured files.
  • 7. Horizon (Dashboard): Web-based graphical interface for administrators and self-service users.
  • 8. Heat (Orchestration): Orchestrates multi-tier composite cloud applications via declarative YAML templates.
  • 9. Octavia (Load Balancing): Delivers scalable Load Balancing as a Service (LBaaS).

VM Creation Workflow: Horizon → Authenticated by Keystone → Image located by Glance → Nova API scheduler chooses host node → Neutron allocates virtual NIC and IP → Cinder attaches block volume → Hypervisor (KVM) launches VM.

[10 Marks] Analyze 3 Real-World Cloud Security Incidents (Capital One, Storm-0558, S3 Leaks) with vulnerabilities and mitigations. ▼

Model Answer:

Case 1: Capital One Breach (2019) — AWS

  • Vulnerability: Misconfigured Web Application Firewall (WAF) exploited via Server-Side Request Forgery (SSRF).
  • Exploit: Attacker queried the EC2 Instance Metadata Service (IMDSv1) at 169.254.169.254 to extract temporary IAM role credentials and exfiltrate 106M records from S3.
  • Mitigations: Enforce IMDSv2 (requires session token header), apply IAM Least Privilege on EC2 instance roles, and encrypt S3 with customer KMS keys.

Case 2: Storm-0558 Token Forgery Incident (2023) — Microsoft Azure

  • Vulnerability: Stolen inactive consumer signing key (MSA key) leaked via corporate Windows crash dump.
  • Exploit: Verification flaw allowed the consumer key to forge enterprise authentication tokens to access Exchange Online inboxes.
  • Mitigations: Strengthen cryptographic key isolation, automate rapid key rotation, and isolate consumer/enterprise token verification.

Case 3: Publicly Exposed AWS S3 Buckets

  • Vulnerability: Accidental assignment of public read permissions (AllUsers) in bucket Access Control Lists (ACLs).
  • Mitigations: Enable AWS S3 "Block Public Access" at the root account level and deploy Amazon Macie (ML scanner) for automated data exposure detection.
